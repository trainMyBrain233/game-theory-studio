# 角色资产与方向合同

本文件是待审核草稿。读取项目现行 AGENTS.md、角色manifest和目标章节数据后再工作；这里只补最容易反复出错的合同。未授权时仅产出审查，不改素材、仓库或对外发布。

## 定位输入

记录基线commit、角色ID、素材版本/校验值、目标镜头和所需能力。现有入口是 `production/src/character-layers.mjs`、`rgba_character_rig.mjs`、`character_adapter.mjs`；路径变化时先查最新入口。

区分稳定 `actor_id`、显示原名、资产ID、矩阵归属与表示形式。显示名来自核实的角色数据，不凭外观猜原名；改名或后续增加植物角色不能改掉原有行/列及支付所有权。眼口、腿或手指烘焙在位图里时，如实标能力，不声称它们可独立运动。

## 坐标必须有名字

对每一层单独记录：原始画布尺寸、原始朝向、准备阶段镜像、准备后朝向、pivot/end点所处空间、父层、场景side、最终朝向。

- 不从“角色A/B”推断每层原图朝向；头、躯干和手臂可能不同。
- 先完成源图到canonical空间的准备变换，再应用场景镜像；二者不能揉成一个无来源的负号。
- 坐标采用连续图像边缘还是像素中心须一致；离散像素反转与几何点镜像的公式不可混用。
- 几何点、alpha轮廓和位图经过相同变换；只改图片不改pivot会留下可见跳动。
- 镜像检查身体朝向、头部、肘弯与抓握；牌中文字单独保持可读，不通过整体镜像把文字反过来。

## 全身与头像保持同一角色

建立角色表示对应关系，而不是先让全身消失、再在矩阵出现无关系的头像。

1. 为起始全身和目标头像选择相同资产版本，并标定脸部参考点与裁切范围。
2. 用明确的世界变换连接二者。改变父容器时，新的局部矩阵由新父世界矩阵的逆与旧世界矩阵求得。保留镜像；父矩阵不可逆则停止该转换并报告。
3. 在转换开始帧保持位置、尺度、朝向和身份一致；路径、缩放、裁切分别有可检查的时间函数。可设计性地淡出身体，不能突然替换成另一角色或错误朝向。
4. 所有状态由显式时间/帧求得，乱序渲染不依赖上次播放状态。

不要按形状相似或颜色猜人物匹配。头像小到无法辨认时应调整构图/裁切，而非声称存在一个头像文件就算通过。

## 验收与负例

复用现有独立方向像素夹具，不退化为读回同一声明。新增内容至少检查：

- 源图、canonical与最终镜头的同层对照；真实美术与原创建模夹具分别记录。
- 左右角色、所有新增手姿、矩阵行/列；改显示名后归属不变。
- 每段改变的转换首尾、25/50/75%及相邻帧；同时间重复和乱序取帧。
- 故意多镜像一次、错用未经准备的pivot、错换actor ID、换父节点却保留旧局部坐标等与本次修改相关的负例。

输出问题、影响帧、预期合同、证据与实际检查状态。几何连续不等于头像好看；尚未看真实素材就标 `UNVERIFIED_ART`。
