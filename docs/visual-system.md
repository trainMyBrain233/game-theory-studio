# 博弈论视频 v2：可复用视觉范式草案

状态：B「清爽教材」已选定；A/C保留为历史对照，已选PvZ普通/路障僵尸，真实分层视觉预览已在云端私下生成/验收，不随MIT源码分发。此文档描述基础模板，公开仓库不含影片；f694678私有视觉预览已有独立证据，当前修复head需重新绑定，仍无真人配音/实际音频对齐。2026-10-08。

## 这次实际改了什么

最初用完全相同的内容比较美术方向；当前采用B。基础模板中的小A/小B仅为角色占位，不代表最终角色外形：小A与小B各选红/蓝牌；收益矩阵保持 `[(3,3),(0,5);(5,0),(1,1)]`；统一聚焦“小A选红、小B选蓝 → (0,5)”。每套包含参与者情境和收益矩阵两张原生1920×1080关键帧。

原画面的暗底、发光、浮动卡片和科技界面装饰被移除。所有人物、牌、箭头和矩阵都是原创 Canvas 路径，文字是真实中文字体，能在同一渲染管线内修改、动画化；没有使用AI生成的图片。

中文字体同时修正：原先把多地区TTC字体简单取名SC，渲染实际读取JP字形。现在明确加载独立的Noto Sans/Serif CJK SC OTF，并验证实际400/700字重。原视频并非“先出720p位图再放大”，也不能仅凭低平均码率认定压缩导致模糊。完整诊断见 `../typography/README.md`。

## 三套提案怎么不同

| 方向 | 核心气质 | 构图和角色 | 矩阵的讲法 | 后续适用 |
|---|---|---|---|---|
| A 纸上编辑 | 杂志编辑、克制、有书卷感 | 大宋体问题；左右非对称；黑白人物和朱红批注；大数字直接承担知识点 | 保留左侧论述栏，右侧一张大表；当前格朱红描边 | 概念导入、章节首尾、重视品牌气质的系列 |
| B 清爽教材 | 清晰、耐看、解释型 | 深蓝黑体；整幅连续线图；对称共享桌面；轻量定义行 | 大表与三步读表说明；行、列、交点有固定位置 | 囚徒困境、最佳回应、纳什均衡等连续推导 |
| C 明快图解 | 有动作感、轻松、醒目 | 粗黑线角色；黄与紫服装；一块宽场景底；大箭头解释相互影响 | 把一个收益格拆成两位参与者的大数字 | 入门短视频、较快节奏、需要直接展示结果的章节 |

当前主方向为B。A/C源码只用于比较与回归检查，不在同一片里随意混用。

三套共用角色身份和案例，是为了公平比较视觉语言。不能仅修改色板就宣称是新风格；版式、线宽、标题字体、强调方式和动画节奏应一起选定。

## Design tokens

## 中文排版规则

1. 只使用明确的独立SC字体。标题可用Serif SC；说明、数据、字幕用Sans SC。真实权重只用400或700，不能把500/600/800当成已存在的字体。
2. 当前提案主标题79–88px；正文36–40px；关键读表说明36px；栏目30px；表头32–36px；数字66–174px；字幕40px/700。小型角色字母徽记是辅助身份，允许24–29px；它旁边必须有较大的“小A/小B”。
3. 无描边假粗体、外发光、文字阴影、字距拉伸或横向压缩。标题最多2行，完整解释不要拆成散落的短词。
4. 正文前后标点用中文全角；数值对在图表内统一半角 `(0, 5)`，行列意义必须明示。A永远在左项，B永远在右项。
5. 关键说明与字幕不能同时塞入过多新知识。章节字幕每行最多22个汉字/字母/数字，最多两行；实际40px左右的字形边界也须通过检查。超出要按语义拆时段或两行，不能一味缩小字体。
6. 正文对底色至少4.5:1，优先更高；静止文字完全不透明。当前三套主文字和次要文字均通过4.5:1检查。视觉上过小仍可能难读，合规对比度不是可读性的全部。
7. 先检查原生1080p，再看960×540显示；手机竖屏内小窗还需单独测试。当前不是9:16竖屏排版，不能简单裁中央就交付竖版。

## 参与者、选择与数值：固定语义

- 小A：圆形A徽记，参与者画面左侧，收益数对第一项，矩阵行。
- 小B：方形B徽记，参与者画面右侧，收益数对第二项，矩阵列。
- 颜色不决定参与者身份。牌的红/蓝是策略，不能同时把红定义为A、蓝定义为B。
- 选中格：仅这一格有浅底/粗描边。不要把其余三个格各涂一种颜色。收益数字通常同色，不能用红=坏、绿=好暗示跨参与者效用可比。
- “各自目标”是让各自得分更高，不是共同利益。“参与者”一般可为个体或组织，本片只用两个人举例。
- 虚构积分仅用于教学，不声称是真实金钱，也不在本章直接把当前选中格称作最优或均衡。

## 可复用图解原语

当前实际可编辑：人物/身份徽记、共享桌面、策略牌、行列选择标记、单向箭头、2×2收益矩阵、当前格、收益拆解、字幕和章节标题。

后续扩展按知识需要增加：

- 信息章：沿用人物和牌，遮住牌面；“公共规则”保持可见；只用遮罩表达不可见，不另加科技锁面板。
- 策略章：一轮用两张牌；多轮用最多三步的条件路线。用实线表示行动，虚线表示尚未观察到的信息，必须有文字说明。
- 最佳回应：同一矩阵不移动；一次固定对方一列/一行，只比较一位参与者的两个数，再出现下划线。
- 纳什均衡：保留双方的最佳回应标记，在交点加双圈与名称。不能直接全表闪烁后突然出现“均衡”。
- 混合策略：保持角色、策略图形，新增一条概率分配条；概率、收益和角色颜色不能混作一种语义。

这是一组有限的教学组件，不是通用自动排版系统。新章节仍需选择恰当构图并逐帧检查，不能仅换标题就生成可信讲解。

## 转场与动效语法（production中已有六节时间线，仍需正片验收）

1. 每镜先出现情境，再出现选择，最后落到结果。图示与旁白逐步同步，一次只新增一个主要关系。
2. 角色身份固定。场景转矩阵时，A的徽记移动到行侧，B的徽记移动到列顶；牌的图形沿用，避免瞬间换一套图例。
3. 页面骨架在章节内持续存在。淡入仅用于引入新内容；不让整张表每解释一格都重新淡入。
4. 推荐起始节奏：进入0.25–0.45秒，关系箭头0.3–0.5秒，重点格0.2–0.3秒；复杂表完成后留至少1.5–2秒纯阅读。精确停留由旁白决定。
5. A以擦出细线、朱红下划线和直接剪切为主；B以逐项填表、移动指示线为主；C允许小幅位移和一次轻缓弹性强调，但文字停稳后不晃动。
6. 禁止无意义光晕、漂浮粒子、循环呼吸和持续镜头缩放。进入动画可有透明度，信息稳定期不可残留半透明文字。
7. 关键事件使用同一时间数据驱动图表、字幕、旁白标记；编码帧必须由时间纯函数生成，不能依赖系统时钟或未固定随机数。

## 最小复用结构

- `../design/scenes.json`：案例、参与者、策略、收益矩阵、当前格、章节标题与字幕。
- `../design/tokens.json`：语义映射、颜色、字号和安全区。
- `../design/render-proposals.mjs`：两个真实场景模板和三套视觉皮肤；导出 `drawScene(canvas, styleId, sceneId, override)`。
- `../design/qa.mjs`：尺寸、原生拼板、确定性、文字边界、字幕尺寸、对比度、四种选择状态。
- `../typography/fonts.mjs`：字体唯一入口。

本次已实现的 `sceneId` 为 `participants` 与 `payoff`。`nextChapterExample` 是后续内容字段示例，还没有对应已完成的信息章动画。production 已增加第一集六节场景与动作，见其README；新章节仍需补场景函数并复用原语。

修改当前收益格可传 `selected: {row: 1, column: 0}`；默认原例的收益显示、实际高亮和说明/字幕一起变成 `(5,0)`。替换案例可用 `override.data`，其 selected 会被保留，显式 selected 具有更高优先级。显示名、策略名和收益由配置驱动；章节口播修改配置后需用 build:narration 重建并重新审查。文案使用实际字号与字形边界，超出有限排版范围时拒绝，不自动缩小。

## 导出与验收

- 源帧PNG：1920×1080、无损、原生绘制；不可先生成小位图再放大。比较板3840×1320，左右两张原图完整嵌入，没有放大或裁切。
- 最终常规交付建议：1920×1080、30fps、H.264、yuv420p、CRF16–18、slow、BT.709、faststart。4K可作为母版，但不能代替正确字体、字号与构图。
- 字幕优先高亮度对比。彩色细线在420色度采样下会变软，重要边框保持至少2px；本提案关键线为3–5px。
- 编码后必须重新抽帧检查，不只验收PNG；完整解码检查报错、尺寸、帧率、时长、色彩标记。原帧→编码帧对照时将字号、字形、文字边缘和收益小数作为重点，不仅看整帧PSNR。
- 当前已通过53项设计自动检查，见生成的 `../design/qa/checks.json`。自动边界检查不能替代视觉重叠检查；新字体、长标题、长字幕和新角色均需重新目视检查。
- 云端已从f694678完成173.3秒私有视觉预览，5199帧解码及189采样帧/37字幕窗独立检查通过；新修复head需重渲重验。真人配音/实际音频对齐与最终平台播放仍未验证，公开placeholder CI不替代私有图层验收。
