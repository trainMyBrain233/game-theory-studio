# Canvas 二维手、牌、桌交互规范

本规范将公开动画资料转为可独立实现的 Canvas 合同，不要求采用特定编辑器或运行时。公式、状态划分与验收方法是工程建议；像素容差、时长和曲线需按画面尺寸与风格调整。它不是当前实验或生产动作已通过的报告。

## 1. Setup pose 与坐标

先验收静止装配，再制作动作。每个独立运动部分单独成图；附件保留裁切偏移、缩放、原始方向及规范方向。锚点必须注明所属坐标系。

建议制作资源统一朝右、x 向右、y 向下，以腕部为手局部原点。原始图先规范化；另一侧角色在场景中镜像规范装配一次。预处理镜像与场景镜像分别记账，锚点和方向向量跟随相同变换。

```text
source → normalized asset → attachment/bone local → character → scene
M_scene_from_source = M_character × M_chain × M_attachment × M_normalize
```

旋转正负与工具坐标约定有关，不直接照搬数值。调试时显示局部轴、腕点、握点和接触法线。负行列式表示反射；肘弯侧应在同一求解空间判定。

牌的几何、握点随场景镜像，牌面文字用可读的局部阅读坐标绘制，并持续附着于同一张牌。

参考：[Spine Images](https://esotericsoftware.com/spine-images)、[Runtime Skeletons](https://esotericsoftware.com/spine-runtime-skeletons)。

## 2. 腕点与握点分离

腕点连接前臂，握点描述指腹与牌的接触，两者不能互换。握点应包含位置和朝向，而非仅一个像素坐标。

若腕为手局部原点，局部握点偏移为 g，手的旋转/缩放为 A，目标握点为 c：

```text
wrist = c - A × g
```

完整框架采用非奇异 3×3 齐次矩阵和列向量。G_hand、G_card 分别把握持框架映射到手/牌局部；G_world 把握持框架映射到场景：

```text
M_hand = G_world × inverse(G_hand)
M_card = G_world × inverse(G_card)
target_wrist = M_hand × wrist_local
```

手臂 IK 求 target_wrist；手掌朝向由抓取设计控制。每帧只保留一个主控握持框架，不能独立补间手、牌后再叠加彼此不同的摆动。肩膀移动时重新求臂，持牌相对关系保持稳定。

接近最大伸展时调整轨迹或身体姿态，不用突然翻肘、明显拉长前臂补偿不可达目标。IK 到达目标只证明可达，不能证明指掌包覆、腕角和遮挡正确。

参考：[Spine Point attachments](https://esotericsoftware.com/spine-points)、[IK constraints](https://esotericsoftware.com/spine-ik-constraints)、[Rive IK Constraint](https://rive.app/docs/editor/constraints/ik-constraint)。

## 3. 七状态合同

| 状态 | 必须成立的关系 | 转出条件 |
| --- | --- | --- |
| idle | 放松手受桌面支撑或自然垂放；牌由桌/场景控制。 | 有动作意图，路径可达。 |
| approach | 牌不动；手沿可读路径靠近，调整掌向与指间距。 | 接近位置、方向正确，闭合不穿牌。 |
| contact | 牌仍不动；指腹闭合，前后遮挡形成。 | 完整接触条件成立，抓取事件触发一次。 |
| hold | 同一握持框架驱动手与牌，相对位姿稳定。 | 放置目标可达。 |
| place | 维持夹持，手牌一起减速到受支撑姿态。 | 支撑成立，运动达到预定稳定状态。 |
| release | 牌转交桌/场景；保持位姿，再打开手指。 | 指牌明确分离，退路无碰撞。 |
| retreat | 牌留在原处；手回到与 idle 注册一致的姿态。 | 速度归稳，循环无接缝。 |

接触条件同时检查位置、朝向、接触区域、可见遮挡、合理腕角和相对速度。握点距离为零只证明一个等式。牌离桌必须晚于抓取成立；手退开必须晚于支撑与释放成立。

状态入口动作只执行一次，不因重复点击或跳帧重放。未抓住时可撤回；抓住后中断需携牌退回或安全放回，不能让牌消失。先保证因果顺序，再调时长。

参考：[Rive Transitions](https://rive.app/docs/editor/state-machine/transitions) 区分转移条件、时长、退出时机和动作；七状态是本规范的应用设计。

## 4. 同一张牌连续换控制权

牌全程保持同一 id、几何与内容，不通过旧牌淡出、新牌重建掩盖跳变。父级切换只改变控制权：

```text
world_before = card.world
card.parent = newParent
card.local = inverse(newParent.world) × world_before
```

抓取时，握持框架可从当前牌位姿初始化：

```text
gripFrame.world = card.world × G_card
```

释放转交桌/场景时同样保留世界变换。这保证瞬时位姿连续，不自动保证速度连续。切换前应匹配运动速度；继续运动时以保存的速度/切线初始化后续曲线。接触与支撑判断必须使用实际求解后的位姿。

放置接近终点时，由支撑目标决定握持框架的终点；不要让独立手轨迹和桌面同时对牌施加互相冲突的硬约束。

## 5. 分层与手姿更换

局部绘制顺序：

```text
前臂/袖口基底 → 后掌/后拇指 → 牌 → 前指腹 → 腕部袖口前缘
```

同一腕骨驱动的附件可以分处牌前后；绘制顺序不必等于父子层级。袖口前缘只遮腕缝。后掌与前指共享腕坐标、比例和握持变换，被遮住的区域留足隐藏补画。

放松手与夹牌手更换时：

- 同时注册腕点、腕轴、腕缝两端；一点重合不能消除旋转或宽度差。
- 使用共同画布或显式裁切 offset，不能按各图 alpha 包围盒独立缩放。
- 手腕在袖口后保持足够不透明重叠，避免旋转露缝。
- 轮廓差异大时增加中间手姿，或选合理的遮挡时机；单纯交叉淡化会产生双掌、双指。
- contact 后到 release 前始终维持夹持轮廓，不能提前换回不接触牌的放松图。
- 先在最终尺寸与正常速度看，再逐帧检查；静帧合格不等于切换合格。

参考：[Spine Slots](https://esotericsoftware.com/spine-slots) 将附件显示与绘制顺序独立于骨骼层级。

## 6. 桌面与支撑

先决定牌的目标姿态：手持竖牌由手支撑；松手后竖牌需要牌架或倚靠等稳定机制；平放牌要进入桌面透视。底边碰到一条线不等于能自行站稳。

桌面至少有可读的顶面、前沿厚度和一致透视。不同深度的接触不应强压到同一屏幕 y；可用桌面投影 P(u,v) 计算支撑位置。严格侧视镜头可简化为支撑线，但相关物件需遵守相同约定。

对设计为贴桌的接触边或区域采样，检查有符号间隙、穿透和是否落在桌面范围内。若支撑法线 n 指向上方：

```text
gap = dot(contactPoint - supportPoint, n)
# gap > 0：离开；gap < 0：穿入
```

接触区域来自姿态设计，不能用 PNG 最低 alpha 像素代替。阴影只辅助表达高度和承托；落桌时贴近，抬起时分离，不能用阴影掩盖错误几何。

## 7. 动画与信息主次

小幅视线或手势预告目标，接触附近减速，放稳后开指，最后收手。弧线和轻微跟随动作服务主要动作；保持夹持时不可让附加摆动破坏接触。

手牌强运动时减少无关文字、数字和符号的强变化；牌拿稳后再强调牌面信息。并非禁止并行动画，而是保证观众能读清动作因果。去掉装饰后仍不清楚的交互，应先修空间关系。

参考：[Adobe 动画原则](https://www.adobe.com/creativecloud/animation/discover/principles-of-animation.html) 中的 anticipation、staging、arcs、ease 与 secondary action。

## 8. 最小验证与失败反例

先用两段臂、后掌/前指色块、同一张几何牌和桌面完成全循环，再替换美术。覆盖左右镜像、不同大小、不同桌面深度、中断、重复触发及变化帧间隔。

检查器必须识别以下坏例子：

1. 握点重合但手绕它错误旋转：朝向/腕角失败。
2. 接触坐标正确但整只手画在牌后：遮挡失败。
3. 仅一个角贴桌，却被认作整边支撑或平放：支撑合同失败。
4. 换父级位置不跳，但速度突然归零：时间连续性失败。
5. 换图腕点一致，腕轴或宽度不同：注册/腕缝失败。
6. 场景重复镜像、牌字反向或文字脱离牌：方向/阅读坐标失败。
7. 目标越过可达边界后翻肘或拉臂：可达性处理失败。
8. 卡底达到桌面高度却越过桌边：支撑范围失败。

保存正常速度循环与各状态边界前后帧。数学检查负责漂移、穿透、跳变和重复事件；视觉复核负责夹持轮廓、重量、腕缝、遮挡和注意力。两者同时通过才放行。

接触距离、角度、速度、停留时长是项目阈值，应绑定最终比例、描边、帧率和节奏；浮点比较精度不能充当美术自然度标准。
