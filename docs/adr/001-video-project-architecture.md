# ADR-001：内容驱动视频工程的模块边界

- 状态：本次边界决策已采纳；第二章扩展方案待实际需求实施。
- 日期：2026-10-08。
- 审阅基线：`92fdc373c9acec4f20e9ae74a799f814aa7c4dbc`，另核对本轮源码打包与无 Git 完整性验证修改；最终交付输入以对应 commit、源码清单与[验证记录](../validation.md)为准。
- 决策：保留 Node Canvas/SVG、Python 工具、单仓库和根命令。先补足交付证据，本轮紧接提取已经重复的转场、缓动和文字出入场模块；章节 registry 与较大目录迁移随第二章实施。本次不迁移渲染框架或引入 monorepo 编排平台。

## 2. 当前基础与真实边界

保留根 npm lockfile、统一 Python 环境与 SC 字体准备流程、共享案例和语义时间轴、Schema 与跨文件语义验证、显式时间驱动、私有角色适配器与原创占位模式、Linux/macOS 最小权限 CI，以及源码与生成物隔离。

当前能力范围如下：

- 第一章有 173.3 秒、30fps、六节的专用整集渲染代码。代码可执行与指定最终影片的音画、角色和媒体验收是不同证据。
- `chapter:new` 只生成章节元数据、两段原创内容和人工参考时间轴，不生成新章分镜、角色动作、音轨或整片。
- `production/src/model.mjs` 固定读取第一章时间轴；`scenes.mjs` 和 `character_adapter.mjs` 引用第一章具体段落 ID。当前不是任意章节 JSON 渲染器。
- 时间轴为人工口播参考；字幕导出、SFX 和正确片长不能证明真实旁白已经对齐。
- 现有私有视觉预览的验证记录绑定 `f694678f2f55d2169f5241f5f9453f203bfdc41e`：173.3 秒、5199 帧、无音轨。该历史证据不能自动认领后续源码；当前修改后的私有影片须重新绑定验收。详见 [project-status.json](../../project-status.json) 与[交付检查单](../delivery-checklist.md)。

### 已核对的依赖边界与技术债

| 代码位置 | 当前事实 | 处理时机 |
| --- | --- | --- |
| `production/src/model.mjs` | 从 `scripts/validate-data.mjs` 导入共享验证；模块加载时读文件，并补齐 CAST/content/TOKENS 对象 | 第二章或同进程多项目预览前提取纯验证，改为显式加载 EpisodeModel；当前单次 CLI 继续使用 |
| `production/src/primitives.mjs` | 同时承担图形、字体注册、文件读取、资产选择、`process.argv` 与逐帧记录 | 下一阶段把 IO/参数解析移到装配边界，绘图接收已准备资源；本次保留已验证路径 |
| `production/src/character_adapter.mjs` | 角色适配器反向读取章节时间轴及 `s08_*` 等事件 | 下一章由编排传入姿态/进度，角色模块仅负责绘制；不复制章节事件查询 |
| 根 `package.json` | Ajv 为 devDependency，生产模型直接导入 | 当前合同是全量 `npm ci`；若支持 `--omit=dev`，须先调整依赖分类并测试，当前不作该承诺 |
| 根与 production Schema | 根采用 draft-07，production 采用 draft2020-12，数据版本各自独立 | 已有严格校验；无需为统一形式移动文件或更换 draft |

这些债务有明确触发条件，不需要重写已工作的渲染器。当前逐帧逻辑经过显式时间与乱序重复帧检查，但尚未改为无 IO、无模块状态的通用纯函数架构。本轮的局部模块提取不等于完成整套纯函数化。

现有完整目录、Schema 与更新入口见[工程与配置契约](../project-structure.md)。根 scenes/tokens Schema 新增 `$id` 与 draft 声明，数据本身没有新增必填 `schemaVersion` 字段。

### 第二章投产时形成的最小结构

```text
chapters/<id>/                内容与语义时间轴
content/cases/                案例事实（届时从 design 拆出）
design/tokens.json            纯共享主题
src/content/                  纯验证与规范化模型
src/render/components/        两章实际复用的矩阵、牌、字幕
src/render/scenes/<chapter>/   每章专属叙事与动作
src/adapters/                 Canvas、字体、角色和编码的 IO 边界
scripts/                      薄 CLI，保留原 npm 命令
tests/                        分层检查
artifacts/<render-id>/         忽略的产物与交付 manifest
```

此结构是后续迁移示意，尚未实施。每次只迁移一个职责，保留旧命令转发，用旧章关键帧与语义回归核对；不要同时重排路径、换字体和改动作。

依赖目标是“入口 → 内容解析 → 章节编排 → 通用绘制 → Canvas 适配”的单向流动。编码器接收帧，不决定教学事实；纯内容与 tokens 不依赖 Canvas、私有角色或 CLI。资源在初始化时准备，单帧画面依赖显式时间、规范化模型与已加载资源。当前表中的反向依赖需按触发条件逐项消除。

内容驱动不要求将所有坐标写入 JSON。姓名、策略、收益、字幕和语义事件须有唯一来源；本章独有的教学比喻与运动编排可保留为代码。提取组件应基于已经出现的实际重复。

### 本轮紧接实施的局部模块提取

以下是已确定的下一提交范围，目前待实现，不能提前计入本次源码验证的完成项：

- 将现有重复的转场、缓动、文字出入场计算提取为纯模块，由主片实际消费。输入为显式时间/进度与配置，计算不读取文件、CLI、墙钟或私有素材。
- 为卡牌、矩阵、字幕和角色层明确接口与元数据：输入模型/时间/资源、坐标与绘制边界，以及资产模式和文本测量记录。保留既有布局和公开/私有适配边界。
- 提供独立演示，并验证至少两个实际场景复用模块；只新增未被主片调用的工具文件不算完成。
- 在同环境、同字体和同配置下比较重构前后关键帧、行为与确定性，维持语义、布局和全量门禁。接口说明需同时标明未支持的参数，不能借抽离扩大章节合同。

章节 registry、显式 EpisodeModel、多项目并发与较大目录迁移仍按第二章实际需求实施。这次抽离须保持旧 npm 命令，不同时改变字体、内容、分镜或角色动作。

## 4. 素材、生成物与可复现交付

### 三类文件

1. **公开源：** 原创代码/SVG、Schema、内容、字体配方与校验、许可证和文档进入 Git。timeline/SRT/口播派生文本是当前用于内容审阅的明确例外；从源重建并检查 diff，默认 QA 临时重建比较，不写回掩盖过期文件。
2. **受控输入：** 私有角色层、录音及不宜公开的资源不进入公开仓库、公开 CI 或公共缓存。保留显式占位模式与缺失私有层的失败行为；忽略文件不等于访问控制或许可证明。PNG 包装进 SVG 仍为位图。
3. **生成物：** 帧、视频、音频导出、联系图、机器报告与 ZIP 放忽略目录，按显式清单交付，不打包整个历史输出目录。公开报告不写私人机器绝对路径或私有素材明细。

### 已处理的源码包交付问题

- `production/pack_source.py` 的 `SOURCE_MANIFEST.json` 记录真实 HEAD、工作区 dirty 状态、`reproducible_from_commit`、分发类型、项目/Schema/章节版本，以及文件字节数与 SHA-256。候选文件可含非忽略的未提交源码；dirty 或无 HEAD 时不声称包内容可由该 commit 直接复现。
- 打包先保存候选源码字节快照；完成前再次核对来源状态和文件字节。打包期间源码变化则失败并保留旧 ZIP；归档使用同一公开源码边界扫描。
- ZIP 不含 `.git`。完整开发、复用夹具、`npm test` 与重新打包仍要求 Git clone；`qa_source.py` 对无 Git 的入口给出明确错误，不承诺“解压即可运行完整开发门禁”。
- 独立 `production/verify_source_archive.py` 不需要 Git、npm、字体或 fontTools，核对列明文件及公开边界，拒绝缺失、修改、符号链接和未列明文件。检查须在安装依赖或生成产物前运行，避免新增产物被误认作归档源。

本轮实际完整源码包已在无 Git 的干净解压目录连续验证两次，并验证修改/新增文件会失败；没有通过 `git init` 掩盖分发限制。完整性验证检查源字节，不等同于签名、依赖安装或影片验收。详细命令与当次文件数见[验证记录](../validation.md)；以后新增源码会改变文件数，不能把本轮数量用作固定合同。

### 每次媒体交付应记录的证据

以下是媒体交付合同，尚未全部自动写入一个统一 render manifest；当前源码包清单只覆盖上节的源码字段。首版可人工整理，后续有批量生产需求再自动化。

- commit 与 clean/dirty 状态；章节、内容、渲染合同版本。
- case/timeline/tokens、字体与实际输入的散列；公共/私有资产模式。私有素材明细保留在受控交付中。
- Node/npm/Python/Canvas/FFmpeg、操作系统/架构、编码参数；如使用随机过程，记录种子。
- 输出的相对文件名、字节数、SHA-256、宽高、fps、帧数、时长和音轨类别。
- 检查命令及 `passed / failed / not-run / not-applicable`，人工观看/试听范围与遗留问题。
- `manual-reference / audio-aligned`、`placeholder / private-production`、`silent / sfx-only / voiceover` 三个独立状态。

散列识别交付文件，不证明版权或视觉质量。同环境同帧可逐像素比较，跨平台检查语义、布局与媒体合同，不承诺 MP4 字节一致。

## 5. 测试与作品完成度分开验收

| 层级 | 核心证据 |
| --- | --- |
| 合同/语义 | 错玩家、收益、选择、超长文本与不支持的合同会失败；派生文本过期能被发现；合法改名/策略/不对称收益/默认 BR 可重建并通过 QA |
| 实际图形 | 四种选牌、实际字重/字族/字号、牌色与非对称收益改变正确像素；字形、文本边界和角色 alpha mask |
| 时间/章节 | 转场起止、25/50/75%及相邻帧；字幕完整阅读窗；事件数组重排和乱序重复帧的确定性 |
| 媒体 | 最终文件 ffprobe、完整解码、实际帧数/色彩/音轨与文件散列 |
| 作品 | 原生与缩小画面检查；完整观看、真实配音试听、字幕/数字重音对齐 |
| 分发 | 文件清单、源码边界、许可证说明、全新 clone 的开发复跑或无 Git 源码归档完整性检查；两类结论分别记录 |

继续用公开原创资产运行 PR 快速检查，长片编码和私有角色检查作为交付验收。公共占位通过不证明私有角色净空通过，媒体可解码不证明教学易懂，旧提交通过不能认领新提交。截图基线须人工审阅后更新。

本轮已修复收益事件按玩家归属绘制、显示名与牌色配置同步、实际字重断言、字体来源复验、SVG 大小写/namespace 边界、只读归档 QA 与合法案例复用门禁。Schema2.1 明确完整格揭示需 A/B 各一个事件；这些修复建立当前有限合同，不意味着新增了通用章节动画或配音能力。当次测试与最终 CI 必须记录实际输入，见[验证记录](../validation.md)。

新章从脚手架到生产仍需：完成内容 → 实现场景/动作 → 注册渲染合同与事件映射 → 资产/布局验收 → 真实音轨重对齐 → 成片编码和完整观看 → 交付清单。修改阶段字段不能跳过步骤。

## 6. 实施优先级与接受条件

**本次验收前：** 第一里程碑先交付本轮正确性、复用、源码包与文档修复；紧接第二里程碑按上节提取重复转场/缓动/文字出入场，明确四类绘制接口与元数据，验证独立演示和两个场景实际复用。各里程碑绑定自己的 commit、回归和 CI。保持现有命令；最终按新源码绑定私有影片检查，补媒体清单、散列、音轨和对齐状态。源码包已提供来源清单与无 Git 完整性检查，其范围不得扩大为完整开发复跑。声称已完成的层级以实际证据为准。

**第一章验收后、第二章投产时：** 显式加载 EpisodeModel，增加章节 registry；迁出共享纯验证；将 IO 从绘图分离；由编排传角色姿态；按两章实际复用提取矩阵、牌与字幕；统一 render-id 输出及复跑测试。每步保留第一章回归。

**有实际触发条件才做：** 多个独立消费者才拆 workspace/package；批量多版本生产才采用缓存或队列；长期归档复现才固定镜像与完整依赖散列；非程序作者频繁调整旁白时才评估事件编辑器或更换框架。

接受条件：新开发者能找到唯一事实源、追溯指定成片的输入与检查、明确第二章还缺什么，并复现文档承诺的范围。目录层数不作为完成度指标。
