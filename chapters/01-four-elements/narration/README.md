文件
- timeline.json：章节、37段字幕/口播、尾停、呼吸位置与精确画面事件参考。
- voiceover_v2_zh.txt：带查找时间码、停顿提示的可录音稿，末尾有纯正文。
- game_theory_v2_zh.srt：全片字幕，完整句/语义块一次显示。
- qa/metrics.json：可复核的字幕密度和时间轴检查结果。
- build_narration.py：人工定时原始稿及生成/校验程序。

时间轴契约
- start/end 是整段字幕显示窗；尾部停顿已经包含在其中。
- voiceover_end 是参考发声结束点；end = voiceover_end + pause_after。
- 不要在end之后再追加pause_after，否则整片会多出31.1秒。
- spoken_duration 包括句内逗号、分号、问句的自然微停，不能理解为必须连续发声。
- breath_points 是可自然换气的位置，不是额外必须添加的空白。
- 录音后，先按真人语义和呼吸对齐，再移动画面事件、SRT和章节边界。不要让人为了卡点赶句子。
- score_reveals.offset 相对于该结果段start，是数值出现的参考时点，并非语音识别结果。
- 转场放在句尾留白中；字幕层完整保留，不逐字打字、不做快闪、不提前退出。

质量检查
1. 速度：最大字幕阅读密度3.33可读字符/秒；只计汉字、字母和数字，不计标点、空格。最密集的是02:28.8–02:36.6的“收益不一定是钱…”段，26个可读字符保留7.8秒，拆成两个语义行。
2. 口播：460个可读字符；参考发声窗合计143.0秒，其中已留句内微停。最快参考发声密度3.83字符/秒。该统计用于定位密集段，不能代替真人试听，也不是通用听觉标准。
3. 停顿：显式句尾/理解留白合计31.1秒，通常0.6–1.1秒；策略定义后1.1秒，收益定义后1秒；收尾2.5秒不给新信息。四个组合的选择和得分分别成段，不挤在一句中。
4. 字幕：37块、最多2行；最长一行19个可读字符（含标点最长22个字符）。所有段的字幕显示时间都长于该段估计发声时长；首尾连续、无重叠、无空洞、文本与口播完全一致。
5. 断句：无跨字幕块拆开主谓、数字、角色名、条件与结果的情况。多轮对照先说“如果改成多轮”，随后说“本片仍然只玩一轮”；“收益不一定是钱”之后换行，后行保留完整举例。
6. 概念密集处：01:04.3–01:15.1先解释本例的两个纯策略，再给策略的一般定义；01:38.2–01:51.3将行、列、数对读法拆成三段；两处均留尾停，屏幕不要另外叠加新术语。
7. 收益核对：A为行、B为列；每格顺序A、B，以共享`design/scenes.json`的当前姓名/策略/收益为准。默认教学例为红红(3,3)、红蓝(0,5)、蓝红(5,0)、蓝蓝(1,1)。先点清双方选牌，再展示对应数值；复用后重建录音稿与时间轴并检查通用读法。
8. 准确性：原例只有一轮，双方追求各自更高得分；规则公开、选择前不知道对手当轮牌面。未将这点误称为“不完全信息”；四问作为入门整理，并非唯一分类。

渲染后仍需做的检查
- 实际导出字幕的字号、换行、画面安全区和停留时长。
- 数字显出时，是否仍清楚对应到该玩家；保留之前已经解释的格子，不重置矩阵。
- 若之后加入真人录音，以完整试听确认换气、数字重音和读完后留白，再调整本参考时间轴。
